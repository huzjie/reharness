# Propose-Probe-Compose（PPC）

这是本框架的核心循环，三步各司其职：

```
Propose   生成 K 个候选 harness（随机子集 / 变异）
Probe     在每个候选下跑 agent，收集执行 trace（成功/失败 + 组件集合）
Compose   对比打分，选出"与成功强关联"的组件，重组成新 harness
```

## 为什么是"对比式"

单看"某个组件出现时成功率"不够（会混入其它组件的影响）。对比式要问的是：
**这个组件出现 vs 不出现，成功率差多少**——这就是 success-lift：

```
lift(c) = P(成功 | c 出现) - P(成功 | c 不出现)
```

一个"必须"组件：出现时任务能解、不出现必挂 → lift 显著为正。
一个"有害"组件：出现必挂 → lift 显著为负。
一个"无关"组件：出现与否不影响 → lift ≈ 0。

于是**选 lift 最高的 top-k 个组件**就逼近最优 harness，全程不需要标签。

## 可复用工程要点

1. 候选要**足够多样**（随机子集比原地微调覆盖更广），lift 才统计得准。
2. lift 要用 **softmax 温度除法**而非缩放（缩放有尺度不变性陷阱）。
3. 中性组件的 lift 是有限样本噪声，排序时别被它挤掉真正的信号。
